# 蓝牙互联控制与音频路由测试报告

## 本次修复范围

- 连接新蓝牙音频设备前，主动断开其他已连接 A2DP 设备，保持单活动蓝牙音频设备。
- 播放、暂停、上一曲、下一曲、快进、后退继续通过 Android `AudioManager.dispatchMediaKeyEvent` 下发到当前系统媒体会话。
- 音量调整统一作用于 `STREAM_MUSIC`，并在有 A2DP 设备连接时返回已同步的蓝牙设备数量。
- 进入蓝牙模块、连接成功、点击播放、调整音量时，主动准备蓝牙音乐路由：
  - 设置 `MODE_NORMAL`
  - 关闭 SCO 通话链路
  - 关闭扬声器强制输出
  - 申请音乐流音频焦点
- Manifest 增加 `MODIFY_AUDIO_SETTINGS` 权限，用于音频路由设置。

## 诊断结论

当前应用实现的是 Android 作为音频源的 A2DP 输出模式，适用于把本机音乐输出到蓝牙耳机、蓝牙音箱、车机等设备。

如果测试方式是“在连接的另一台手机上播放音乐，期望当前应用接收并播放声音”，这属于 A2DP Sink/蓝牙音频接收端能力。普通第三方 Android 应用没有公开 API 能直接接收另一台手机推送的 A2DP 音频流，该能力依赖系统 ROM、系统蓝牙服务和系统签名权限。

## 兼容性注意事项

- Android 12 及以上需要用户授予蓝牙扫描/连接运行时权限。
- 不同厂商 ROM 对三方应用调用 A2DP `connect/disconnect` 的限制不同；若系统拒绝直接连接，界面会保留当前页面并提示重试。
- 多蓝牙音频设备同时输出不是 Android 标准三方应用可稳定控制的能力，本次实现以“单活动设备控制”为准，音量同步作用于系统音乐流。
