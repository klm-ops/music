# 蓝牙连接修复测试报告

## 修复范围

- 模块：蓝牙音乐
- 目标：解决未配对或新发现蓝牙设备无法从蓝牙音乐界面完成连接的问题
- 影响文件：
  - `app/src/main/java/com/app/music/MainActivity.java`
  - `web-player/app.js`
  - `app/src/main/assets/player/app.js`

## 根因分析

1. 未配对设备的连接链路不完整：前端先调用 `pairBluetoothDevice()`，原生层只发起系统配对并返回，配对完成后不会自动继续执行 A2DP 连接，用户必须再次点击连接。
2. 前端等待配对的时间固定为 1.8 秒，实际系统配对弹窗和用户确认经常超过该时间，导致 pending 状态提前清除。
3. A2DP profile 代理未就绪时，原生层直接返回“稍后重试”，没有自动排队重试。
4. 前端在“已请求连接”时提前切换到已连接面板，容易出现 UI 显示已连接但系统 A2DP 路由未建立的假连接状态。

## 修复内容

- 原生层新增待连接地址和重试流程：
  - 配对成功后自动继续连接 A2DP。
  - A2DP 服务未就绪时自动短间隔重试。
  - A2DP 连接确认超时后清理 pending 状态并提示用户。
- 原生层新增 `BluetoothA2dp.ACTION_CONNECTION_STATE_CHANGED` 监听：
  - 区分 A2DP 正在连接、已连接、已断开。
  - 只有收到 A2DP 已连接后才清理待连接状态。
- 前端连接流程调整：
  - 未配对设备也统一调用 `connectBluetoothDevice(address)`。
  - 不再把“已请求连接”当作真实连接成功。
  - 通过原生广播和 `getBluetoothDevices()` 刷新结果确认连接状态。

## 通过标准

- 搜索：设备名称完整显示，搜索完成后按钮恢复。
- 配对：未配对设备点击连接后触发系统配对，确认配对后无需再次点击即可继续连接。
- 连接：A2DP 状态变为 connected 后前端才显示已连接和播放控制。
- 稳定性：连接后连续播放或待机 10 分钟不主动断连。
- 耗时：已配对设备连接建议小于 8 秒；未配对设备从确认配对到连接成功建议小于 15 秒。

## 风险说明

Android 普通三方应用对 A2DP 直接连接能力受系统版本、厂商 ROM 和设备策略限制。代码已保留系统蓝牙设置兜底：当系统拒绝应用直接连接 A2DP 时，会打开系统蓝牙设置，由用户完成连接。
