# 蓝牙稳定性与音频输出诊断报告

## 问题 1：连接后自动退出连接态

### 根因

前端在发起连接后设置了 12 秒确认窗口。如果原生层没有在该窗口内返回 A2DP `connected` 状态，前端会主动清空 `connectedBtDeviceId`，表现为用户不操作或正常操作时蓝牙音乐界面自动退出连接态。

另外，原生层曾把部分普通 ACL 链路变化直接发布为“设备已断开”。这类广播不一定代表当前 A2DP 音频链路断开，会导致界面误判。

### 修复

- 前端不再因为轮询未拿到 A2DP 确认而主动清空连接态。
- 连接态只在用户主动断开或收到明确的“蓝牙音频设备已断开”事件时退出。
- 原生层新增 `confirmedBluetoothAudioAddress`，用于抵抗 A2DP 状态短暂抖动。
- 普通 ACL 断开不再直接触发蓝牙音乐断开，只显示链路状态更新。

## 问题 2：连接手机后播放音乐无声

### 诊断结论

当前代码使用的是 Android 标准 `BluetoothA2dp` 作为音频输出控制路径，即本机作为音频源，把本机音频路由到蓝牙耳机、音箱等外设。

如果需求是“另一台手机通过蓝牙把音乐推送到当前 Android 应用并由当前设备播放”，这属于 A2DP Sink/蓝牙音频接收端能力。普通三方 Android 应用没有标准公开 API 直接接收另一台手机的 A2DP 音频流。该能力通常需要：

- 设备系统 ROM 支持 A2DP Sink；
- 系统级蓝牙服务开启 Sink profile；
- 应用具备系统签名权限或厂商开放接口。

因此，本次代码层面可以修复连接状态误判和误断开，但无法仅通过普通应用代码保证“手机端播放的音乐由本应用接收并输出”。
